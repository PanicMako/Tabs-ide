# Embedded Code-OSS production-readiness audit

Date: 2026-09-09

## Executive summary

The instability was not one bug. Tabs replaces VS Code's Electron main process with a custom host, and several contracts that stock VS Code assumes are always present were missing or only partially emulated. The observed failures map to five concrete causes:

1. `nativeHost` calls were silently accepted but returned `undefined`, including clipboard writes and external URL launch.
2. Extension OAuth URLs could leave the workbench but there was no route for the OS callback to reach the renderer's registered URI handler.
3. Assistant view containers changed location according to transient activation state, while webview resolution was also serialized behind the extension host's activation-complete acknowledgement. Together these produced a ready-but-empty iframe even after Claude had registered its provider.
4. The Copilot production bundle externalized runtime modules which packaging then omitted; webview resources were also proxied through `fetch(file://...)`, which intermittently returned empty or incorrectly typed worker/WASM bodies.
5. Tabs treated its outer AI-provider preference as Code-OSS extension enablement and wrote `chat.disableAIFeatures` differently into individual project profiles. Upstream reacts to that setting by stopping and restarting the extension host, canceling authentication and chat RPCs during startup.

These are host integration defects, not ordinary extension bugs. The repaired paths now follow the same boundaries as stock VS Code: native operations terminate in Electron main, URI callbacks are sent through the renderer `urlHandler` IPC channel, extension views have a stable container location, provider resolution can proceed as soon as registration occurs, and custom protocols return exact file bytes with explicit MIME types.

## Research baseline

- VS Code webviews run in isolated contexts and load local resources through controlled URI/protocol translation; worker assets must be delivered as real resource bytes with a valid content type. See the official [Webview extension guide](https://github.com/microsoft/vscode-docs/blob/main/api/extension-guides/webview.md).
- Authentication from an extension is expected to combine `window.registerUriHandler` with `env.asExternalUri`; in desktop builds, the application must own the protocol callback and return it to the correct window. See [Remote Development extension guidance](https://github.com/Microsoft/vscode-docs/blob/main/api/advanced-topics/remote-extensions.md?plain=1) and VS Code's [GitHub authentication implementation](https://github.com/microsoft/vscode/blob/main/extensions/github-authentication/src/githubServer.ts).
- Stock VS Code wires an Electron URL listener to a URL service and routes its `urlHandler` IPC channel to an active or explicitly identified window. See [VS Code Electron main](https://github.com/microsoft/vscode/blob/main/src/vs/code/electron-main/app.ts), [URL IPC routing](https://github.com/microsoft/vscode/blob/main/src/vs/platform/url/common/urlIpc.ts), and the [extension URL handler](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/services/extensions/browser/extensionUrlHandler.ts).
- External browser launch is a native-host responsibility in the desktop workbench. See the stock [Electron workbench window implementation](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/electron-browser/window.ts).

## Release blockers still requiring runtime proof

The implementation is materially more reliable, but production readiness should not be declared solely from unit tests. Before release, run a packaged-app matrix on macOS, Windows, and Linux that proves:

1. Explorer Copy Path and Copy Relative Path mutate the system clipboard.
2. Rename, Save As, and open dialogs work against local and remote workspaces. New File, New Folder, save, and delete/trash are now live-verified for a local macOS workspace but still require Windows/Linux and remote-workspace coverage.
3. GitHub/Copilot login completes from browser launch through callback and token persistence, including a second application launch on Windows/Linux.
4. Claude's supported secondary view and Copilot views remain in the auxiliary bar across cold start, reload, disable/enable, uninstall/reinstall, and delayed activation; Claude's primary fallback remains in the primary sidebar for older hosts.
5. A representative extension corpus exercises webviews, WASM workers, terminals, authentication providers, secrets, file watchers, and native dialogs.
6. Keep the automated native-host contract inventory at 100%, and runtime-test the platform-specific implementations on their owning OS.
7. Account and secret persistence survives restart without the historical safe-storage decryption errors.

The most important long-term change is procedural: treat the embedded Electron main-process surface as a versioned compatibility layer. Each Code-OSS update should diff the upstream native-host and URL/webview IPC contracts, with automated tests failing when a newly used method is not implemented.
