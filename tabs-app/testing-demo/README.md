# Small Playwright demo for Tabs

This is a real Playwright test project, not a simulated green run. It reuses the already-installed Playwright 1.61.1. No new platform dependencies or model calls are required to run the supplied test.

## Run from the Tabs terminal

From `tabs-app/testing-demo`:

```sh
# Check that configuration and tests load (does not launch a browser).
bun ../node_modules/playwright/cli.js test --list

# Execute the read-only public OrangeHRM smoke test.
bun ../node_modules/playwright/cli.js test tests/orangehrm.spec.ts

# Inspect failures and traces in the generated report.
bun ../node_modules/playwright/cli.js show-report
```

If Chromium is missing, install the matching official browser with `bun ../node_modules/playwright/cli.js install chromium`.

The test visits Login -> Dashboard -> Employee List -> Time. It does not change employee records. The public site is shared and may change; failures remain failures. Test discovery has been checked, but live OrangeHRM execution is not yet certified.

## Official recording (optional separate browser)

```sh
bun ../node_modules/playwright/cli.js codegen --target=playwright-test --output=tests/recorded.spec.ts https://opensource-demo.orangehrmlive.com
```

This opens Playwright's own browser/Inspector, NOT the Tabs embedded preview. It is an optional upstream reference, not a completed embedded-recorder integration. Use a fresh output filename if preserving a previous recording. Review recorded code and assertions before running it.

## Official generation and repair

The `.claude/agents` files and `.mcp.json` are generated by the installed official Playwright `init-agents --loop=claude` command. Open this folder as a project in Tabs when using its Claude integration. Agent/MCP discovery depends on that integration supporting project-local configuration; restart the agent session if needed. These files alone do not wire the Testing workspace buttons to Playwright agents.

Ask the planner to review `specs/orangehrm.md`, the generator to validate and implement it, and the healer to diagnose a named failed test. Model-backed steps consume provider usage; the supplied deterministic test does not.

Repair rule: propose a diff, retain the original assertions and rerun after review. Do not accept `test.skip`, `test.fixme`, swallowed errors or removed assertions as successful healing. Upstream healer instructions are stricter locally to enforce this.
