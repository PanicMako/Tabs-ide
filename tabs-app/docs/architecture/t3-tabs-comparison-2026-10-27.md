# T3 Code and Tabs: workflow comparison

Reviewed 27 October 2026. Upstream fetched revision: `1702d55214bdbae12278462e572b35e7c0eb4a46` (27 October). Tabs assessment uses the current local working tree, including the changes described below. This is a source and interaction audit of the agent workspace, composer, Git context, and relevant performance work; it is not a complete equivalence audit of every T3 feature.

## Independent repair status (29 October 2026)

The package table and verification summary below are Antigravity's historical implementation claims, not a production-readiness certificate. Independent review reproduced legacy MCP failures, found wrong-thread merge-back translation, stale script choices after machine changes, incomplete PR-card wiring, and missing live-body recovery. See [the repair audit](t3-parity-repair-audit-2026-10-29.md) for the current changes and fresh evidence.

Live events now retain their complete bodies; live deduplication is disabled pending a recovery protocol. Snapshot deduplication remains opt-in. Legacy tools are registered with their original validators in the actual MCP registry, and read-only operations remain separately approved. This correct compatibility path measures 73,118 bytes of tool-list JSON, replacing the unsupported 59,160-byte claim. No provider quality or token-usage improvement has been reproduced.

## Main finding

T3's advantage in the supplied screenshots is a coherent presentation of context: machine, checkout/worktree, branch, pull request, scripts, and Git actions are available together. Tabs already has many of these capabilities, but distributes them across the composer, workspace actions card, Git tool, and companion panels. Copying T3's colors or replacing the whole application would not address that fragmentation.

The strongest direction is to retain Tabs' embedded IDE and additional tools while sharing context and controls more consistently across the agent workspace.

## Composer tray

The requested treatment is an inset layer behind the prompt card, with a narrower width, curved lower corners and reverse curves where it meets the front card. The front composer retains its existing model, permissions, attachment and send controls.

The implementation now keeps the selector tray in the same form, behind the front surface, with normal button semantics so selectors do not send a message. It uses the card color and theme tokens rather than a hard-coded gradient. Current checkout, new worktree and branch operations remain functional. The local machine selector is hidden when there is only one connected machine; a local server label is not evidence of a configured remote connection.

The new-worktree branch menu includes Start from remote when remote branches exist. It stores an explicit remote ref and fetches before creating the worktree; fetch failure prevents creation. A shared cached branch-to-PR lookup provides PR context even when lightweight Git status omits it. No repository-specific PR number is hard-coded.

## Performance claim: what is actually supported

There is no verified basis here for saying the entire T3 application became 100 times faster. Several recent merged improvements are real, but measure different workloads. The figures below are the PR authors' reported benchmarks, not measurements reproduced on Tabs.

| Change                                                                                     | Status verified on GitHub | Reported result                                                                                        | Meaning for Tabs                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------ | ------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [#24899: on-demand workspace capabilities](https://github.com/pingdotgg/t3code/pull/24899) | Merged 25 October         | App plus seven thread opens transferred 8,528 KB versus 1,296 KB, about 85% less.                      | Ported as an opt-in transport: metadata snapshots omit workspace data and explicit refreshes return only the requested provider/workspace. Legacy callers retain full payloads. The 85% number is upstream’s benchmark, not a Tabs measurement.                  |
| [#24723: defer older settled threads](https://github.com/pingdotgg/t3code/pull/24723)      | Merged 25 October         | Initial shell JSON fell from about 2.0 MB to 129 KB in the reported 936-row case: 93.5% less raw data. | Requires paging, exact counts, search, family hydration, reconnect and cache support together. Copying only the 25-row limit would lose discoverability.                                                                                                         |
| [#24647: deduplicate message bodies](https://github.com/pingdotgg/t3code/pull/24647)       | Merged 25 October         | Cold thread payload gzip size fell 18.3%; a Node parse/decode/restore benchmark fell about 8%.         | Ported for opt-in initial/fallback thread snapshots and the projection read endpoint. Exact bodies are restored before callbacks, UI or cache. Live event bodies remain complete following the independent repair. No whole-app speed claim follows from it.     |
| [#23178: new highlighting engine](https://github.com/pingdotgg/t3code/pull/23178)          | Merged 25 October         | File-preview cases improved about 3.5–7 times; a 156-file Node diff benchmark improved about 25 times. | Tabs now uses @pierre/diffs 1.6.1/highlights with a matching incremental renderer and tokenizer disposal. Tabs had no existing upstream custom dependency patch to migrate. Real worker-backed split/unified diffs and streaming-prefix correctness were tested. |
| [#4829: Windows process sampling](https://github.com/pingdotgg/t3code/pull/4829)           | Closed without merging    | About 100 times fewer CIM queries in the example Windows process scan.                                 | This is neither a shipped 100-times app improvement nor a direct macOS benefit. It may explain one version of the rumor, but that attribution is uncertain.                                                                                                      |

Tabs already has a shell snapshot path that omits message bodies. Its orchestration-v2 ProjectionSnapshotQuery builds that shell with empty messages and loads checkpoint context per shell thread. Therefore, it would be inaccurate to say Tabs always loads every full conversation at startup. The newer upstream settled-thread paging remains unported. On-demand capability flags have now been implemented with legacy-client compatibility. Similar intent does not establish identical protocol behavior.

The highlighting upgrade also has tradeoffs: some languages fall back to plaintext and token colors can change. The follow-up measures isolated tokenization and checks rendering correctness; whole-app startup and interaction latency still require representative end-to-end benchmarks.

## Integration order and status

1. The highlighting engine, compact MCP schemas, bounded model catalog, shorter shared instructions, on-demand workspace snapshots and snapshot-body dedup are implemented and tested below.
2. The workspace card now exposes existing Git/context capabilities and newly connected agent/automation controls. It retains Tabs’ styling and divergence tools.
3. Remaining protocol work should start with older-settled paging as one coherent port, preserving exact counts, direct links, search, family hydration and reconnect behavior.
4. Remaining UI parity work is tracked explicitly in the follow-up table: full relationship graph, cross-model manual targeting, automation management, repository script-file support, richer PR metadata and shared selector/density behavior.
5. Production comparisons should use matching window scale and test disconnected machines, dirty checkouts, existing worktrees, permission failures, streaming and keyboard navigation.

## Follow-up implementation: workspace and agent workflow

The card now uses four groups: project/workspace context, version control, sub-agents, and automations. Editor choice is a full-width row. Project identity, Tabs’ surface/corners, PR context, neutral divergence controls and Git actions remain. Only configured remote machines produce a machine chooser. Escape and close restore focus to the workspace toggle.

The sub-agent section uses the existing active-thread V2 stream. Token-only events do not cause a second subscription or polling loop. Rows show real status, model, progress and result; app-owned child conversations can be opened and stopped. Delegation uses the active run’s model and the thread’s permission policy, without escalating access. The server revalidates the active parent run. Idle conversations explain why delegation is unavailable. Forks use the latest stable source; completed fork results can be merged back into their parent. Provider-native child conversations show a read-only notice directing questions and approvals to the parent.

Automation data is subscribed only while its section is expanded, and cleanup disposes the subscription. Only tasks bound to the current thread appear. Interval/daily creation and editing preserve the selected workspace, model and policy; editing a weekday-based daily schedule preserves its weekday mask. Daily times follow the workspace machine’s local zone, as the existing scheduler defines. Existing webhook tasks can be listed, toggled and run; webhook configuration and deletion are not yet exposed by this panel.

## Measured Tabs changes

- All 75 current MCP tools go through the compact-schema adapter. Advertising the same tool registry shrank from **79,364 to 66,764 UTF-8 bytes (15.9%)**. Runtime validation and tool identifiers stay intact.
- Shared orchestration instructions shrank from **6,600 to 2,774 UTF-8 bytes (58.0%)**. ACP-only fallback instructions are appended only for ACP-backed sessions.
- The capabilities tool returns eight models per provider by default, prioritizing the inherited/default/custom choices. Search, pages and explicit `includeAll` preserve discovery of the full catalog; delegation validates against all models.
- Provider workspace snapshots are fetched on demand, merged by provider and working directory, and excluded from general metadata broadcasts for opted-in clients.
- Opted-in thread snapshots remove exact repeated bodies, with lossless restoration at the client boundary. A long repeated-text fixture transfers under half the raw JSON and round-trips exactly. This is a fixture result, not a production gzip measurement.
- Tabs Dark and Tabs Light use **#0E2AF3**, taken from the signature SVG. Shell and embedded theme derivation agree. Monotone presets remain neutral.

A local Node tokenization comparison used three actual repository files, one warmup plus three measured calls with distinct comment suffixes to avoid same-input caching. Median results:

| Input                            | 1.2.7 / shiki-wasm | 1.6.1 / highlights |
| -------------------------------- | -----------------: | -----------------: |
| ChatView.tsx, 254 KB             |          283.70 ms |            3.03 ms |
| OrchestratorMcpService.ts, 93 KB |          113.62 ms |            1.17 ms |
| index.css, 80 KB                 |          140.26 ms |            1.35 ms |

The new outputs contain 12–16 token colors, rather than plaintext fallback. These timings isolate warm tokenization on this machine; they exclude application startup, network, layout, React rendering and user-perceived latency. They are not a claim that the entire app is 100 times faster. Engine changes can change token colors. Streaming-prefix tests cover eleven languages, both engines, edits, CRLF and completed-line identity; the browser fixture renders real highlighted split/unified diffs through the worker pool.

## Theo’s context claim

The post describes tool-use/context improvements, not a general renderer speed multiplier. Upstream [#25423](https://github.com/pingdotgg/t3code/pull/25423) compacts tool schemas and consolidates action tools. [#25790](https://github.com/pingdotgg/t3code/pull/25790) fixes compaction at the full toolkit registration boundary; [#25785](https://github.com/pingdotgg/t3code/pull/25785) adds context-budget checks. Tabs now compacts the complete registry and has an actual-registry size regression test, while retaining its existing tool names for compatibility. The screenshot’s 79% figure is T3-added context in its measured tool-search configuration and date comparison. No paid model tool-quality evaluation was run here, so the advertised 4× result has not been independently reproduced in Tabs.
