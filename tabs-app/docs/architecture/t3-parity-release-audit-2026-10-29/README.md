## Measurement and practical limits

`transport-benchmark.json` records a deterministic synthetic dataset, raw/gzip bytes and decode/restore timings using the production helpers, with exact-restoration assertions. Its values are not production telemetry or a universal speed claim. Memory deltas are GC-sensitive and are not peak-memory savings. The live trace uses the production server deduper and shared restoration helpers with full equality assertions. It measures 65.15% less JSON and 44.14% less gzip data on its synthetic trace. The same 10,000-shell dataset compares full loading with 100 recent shells plus a 25-shell page; this is initial-transfer measurement, not a claim that loading the entire history is free. React DOM render cost and end-to-end latency are explicitly unmeasured. The small configured-provider tool-use evaluation is recorded separately.

The context ratchet now separately checks provider-facing name/description/input descriptors (73,118 UTF-8 JSON bytes) and complete registered descriptors including annotations and output schemas (170,787 bytes). Claude/Codex injected instruction baselines remain 4,174/6,245 bytes. The existing three budgets were not raised; the new full-registry metric closes a measurement gap. These serialized descriptors are not an assertion of actual model input tokens. `tool-use-live.json` keeps estimated schema tokens separate from provider-reported token usage and does not claim independently inspected results where the projection omits them.

Visual acceptance uses Chromium component fixtures with mocked actions and explicit theme tokens, alongside actual Electron/native screenshots. The reduced-motion check verifies the CSS hook and media rule; it does not emulate the OS preference. The narrow-pane case is not a claim of native OS scaling or browser zoom coverage.

Local desktop acceptance is macOS arm64. Windows/Linux installer signing, packaging and platform-specific smoke must pass the normal release CI. The configured-provider test covers one Codex model and a minimal task, not every provider/model combination or T3's claimed tool-quality gains. No 4x tool quality or 79% context reduction is claimed.

No user-data reset or new SQLite migration is required. Roll back using reviewed reverts of these scoped repair commits, never by resetting the user's original working tree. Integration must use this repair branch; releasing only Antigravity's original head omits the fixes.
